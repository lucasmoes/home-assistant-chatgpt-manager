# Connect any compatible MCP client

Install the add-on, set its connection password and dedicated HTTPS `public_url`, and route the entire origin to port 8765. See [installation](../README.md#set-up-in-the-browser). All clients use `https://YOUR-MANAGER-HOST/mcp` with Streamable HTTP. Server-to-server/native clients must support OAuth authorization code with S256 PKCE and browser consent. Browser JavaScript clients on other origins are not enabled by CORS.

## Registration choices

**Configured public clients (no open registration):** keep `oauth_dynamic_registration: false` and add an entry through the add-on YAML configuration:

```yaml
oauth_clients:
  - client_id: my-ai-client
    client_name: My AI client
    redirect_uris:
      - https://client.example.com/oauth/callback
```

Copy the real callback from your client. IDs must be unique letters/digits/underscore/hyphen; the existing `home-assistant-manager` and `home-assistant-manager-claude` IDs are reserved. Up to 32 configured clients and 10 callbacks each are allowed. These are public clients: configure client ID, no secret, scope `ha:manage`, and use discovery. They receive authorization-code and rotating refresh-token support. HTTP is allowed only for `localhost`, `127.0.0.1` and `[::1]` loopback callbacks; custom schemes, fragments, credentials and wildcards are rejected. Configured callbacks match exactly, including port and query.

**Dynamic client registration (DCR):** set `oauth_dynamic_registration: true`, save and restart. Discovery then advertises `/oauth/register`. Let the client register automatically with RFC 7591 JSON metadata. It must send `redirect_uris`, and should send `client_name`, `grant_types: ["authorization_code", "refresh_token"]`, `response_types: ["code"]` and its supported `token_endpoint_auth_method`. Supported methods are `none`, `client_secret_basic` (the RFC default when omitted), and `client_secret_post`. Confidential client secrets are generated by the OAuth provider. PKCE is required even with a secret. No client-credentials or implicit grant is supported.

Registration is unauthenticated when enabled, but grants no home access: owner login and explicit consent are still necessary. Client names are self-reported labels; check the displayed callback before approving. Registration is limited to 10 attempts/minute and 100 persistent dynamic clients per instance. Bodies are limited to 56 KiB by the provider. Registration management is disabled: no client-update/delete token is issued. At capacity, use configured clients or rotate the connection password/restart to clear all registrations and grants, then reconnect. Do not rotate routinely, since all clients lose access.

For native DCR clients declaring `application_type: native`, the provider applies RFC 8252 loopback port matching; host/path remain bound to the registered callback. Otherwise callbacks match exactly. Metadata that could fetch remote keys, sectors or request objects is rejected for DCR. Arbitrary CIMD URLs are not fetched; ChatGPT's existing allowlisted CIMD integration remains a compatibility adapter. Other providers should use DCR or configured public clients.

## OAuth contract

| Field | Value |
| --- | --- |
| MCP/resource URL | `https://YOUR-MANAGER-HOST/mcp` |
| Authorization server discovery | `https://YOUR-MANAGER-HOST/.well-known/oauth-authorization-server` |
| Protected resource metadata | `https://YOUR-MANAGER-HOST/.well-known/oauth-protected-resource/mcp` |
| Authorization endpoint | `https://YOUR-MANAGER-HOST/oauth/authorize` |
| Token endpoint | `https://YOUR-MANAGER-HOST/oauth/token` |
| Revocation endpoint | `https://YOUR-MANAGER-HOST/oauth/revoke` |
| Scope | `ha:manage` |
| PKCE | `S256`, required |

Send `resource` with the canonical MCP URL in authorization and token requests. For compatibility with older clients, omitted resource defaults to this server; another audience is rejected. Use bearer access tokens in the Authorization header. The Home Assistant Supervisor token never leaves the add-on. `write_access` is enforced for every client; scope does not override it.

Ordinary restarts preserve clients and tokens. Changing password, public URL, legacy callback, configured clients, DCR policy or write access revokes all OAuth state at restart. New defaults preserve the existing 0.2.x state fingerprint when no additional clients or DCR are configured. There is no per-client write policy or Home Assistant user-level RBAC.

## Compatibility boundary

MCP is the portable interface. Host plugin manifests, skills, account availability and user interfaces are provider-specific; an AI product without remote MCP/OAuth support cannot connect just because its model is supported elsewhere. This server does not invoke an AI provider API and needs no AI API keys. See [ChatGPT](chatgpt.md), [Claude](claude.md) and [Gemini CLI](gemini.md).

Verify login, consent, tool discovery, a real read and read-only write rejection in each actual client after deploying. Current tests use simulated clients and no live Home Assistant installation. [MCP authorization specification](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization).
